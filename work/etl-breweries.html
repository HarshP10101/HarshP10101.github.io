03 Data engineering / ETL

ETL Breweries Pipeline

What makes a pipeline safe to run again?

3 layersbronze, silver and gold

Tools & sources

Python · MySQL · SQLAlchemy · Docker

View project on GitHub ↗

01 / Context

Why it mattered

A one-off import can get records into a database. A recurring job also needs a way to identify changes, trace source payloads and surface bad records before they reach analysis.

02 / Method

How I approached it

I staged REST API payloads in bronze, standardized records in silver and built analysis tables in gold. Payload and row hashes support deduplication and change detection. Run logs track checks for primary keys, coordinate ranges and whitespace.

03 / Findings

What came out of it

The pipeline loads the API data into MySQL and supplies SQL-ready outputs with an audit trail. Docker packages the database setup and SQLAlchemy handles the database connection.

04 / Takeaway

What I learned

Keeping raw history separate from cleaned records makes it easier to trace how a source change reached a downstream table. Checks and logs make that behaviour inspectable across runs.
